# Journal: 2026-08-17

One day of work on Qwen3.8-27B decode speed (single RTX 3090, llama.cpp).
Start of day: image v10, 54k-deep agentic decode 69.3 tok/s.
End of day: image v11 + stacked n-gram drafting — file-editing sessions decode
at 237–288 tok/s warm, one-shot depths gained 5–6%, and output is still
byte-identical to the unmodified model.

## Shipped

1. **Patch 0007 + truncated drafter (image v11).** The MTP drafter's
   248,320-row output head is 74% of every draft pass. Cut it to 49,152 rows
   (98.5% held-out coverage) with a `d2t` remap, reusing llama.cpp's EAGLE3
   idiom. Same-image A/B: mid-1k 75.0→79.6, 7k 64.7→68.2, 53.4k 59.4→62.9
   tok/s; −546 MiB VRAM; sha256-identical output on every payload. The gate
   measurement that justified the build: one draft step costs 2.25 ms marginal
   against a ~1.2 ms byte floor, so removing 0.6 GB of head reads had to pay.
2. **Stacked n-gram drafting** (`--spec-type draft-mtp,ngram-mod`,
   config-only). ngram-mod drafts long verbatim copies from a host-RAM table
   and preempts the MTP drafter only when it finds a long exact match; MTP
   handles all other rounds. 8-turn cumulative file-editing session: 108.8 →
   237.2 tok/s warm (+118%). Zero VRAM. Worst case measured: −2.9% on a
   deliberately pathological self-repeating 54k prompt.
3. **`--spec-ngram-mod-n-match 32`** (default 24). A longer match key cuts
   false fires: session 198.6 → 260.8 tok/s overall, and the pathological
   worst case recovers to −1.7%.

## Measured and rejected

- **Embedded-MTP mode** (drop `--model-draft`): draft logits route through the
  target's Q8_0 head — −1.6% speed for −0.9 GiB. Keep the separate drafter.
- **SGLang** ("beyond 100 tok/s"): real numbers, but RTX 5090/Blackwell NVFP4
  only; SGLang cannot currently load 4-bit weights for this architecture on
  Ampere (Marlin repack rejects the GDN projection widths; the non-Blackwell
  fallback PR was reverted). Bandwidth-normalized to a 3090 it predicts ~80
  tok/s — parity with this stack. Its profiling usefully confirms quantized
  GEMM ≈77% of a single-card decode step.
- **llama.cpp v0.1.0**: a versioning milestone; 9 commits, none touching CUDA,
  speculation, or the server. No rebase.
- **Wave 8 premise** (MMQ x-tile load pipelining): falsified by ncu. The
  stock kernel sits at 56% of DRAM peak because of SM residency, not load
  scheduling; cp.async is structurally impossible for the x tile (nibbles
  unpack on the way into shared memory); full register pipelining recovered
  only 2.9–3.3 µs of a ~31 µs step (~+1.3% end to end). NO-GO.

## In review (not shipped)

- **MMQ small-batch composite** (arm G grid change + type-agnostic y-tile
  double buffer, one env var): −2.28 ms/forward against true stock, projects
  +5.2% decode. Correctness 1267/1267. Load-bearing methodology note: the
  composite binary's env-off state is 5.2% *worse* than stock (the grid
  config is compile-time), so any A/B needs an external stock reference.
  Owed before ship: shape gate for two known regressions, e2e A/B, KLD,
  other-model smoke.
- **Quant diet** (IQ4_XS / Q4_K_S): downloaded, then paused deliberately —
  first intentionally lossy lever of the campaign; needs a full quality
  battery and would ship only as an opt-in model id, if at all.

## New instrumentation

- `tools/episode.py` — north-star metric: a deterministic 12-turn agentic
  coding episode over the real chat template (reasoning tokens count), with
  per-turn correctness checks. Baseline on prod config: **123.2 s wall,
  17/17 checks** (19.5 s prefill, 103.4 s decode, 11,124 tokens).
- `tools/session_bench.py` — the 8-turn cumulative file-editing session used
  for all n-gram measurements. One-shot benchmarks cannot see this technique;
  the session is the honest workload.
- A 25-item, 3-tier, machine-checked reasoning-effort battery (medium vs
  xhigh, pre-registered decision rules) — running at time of writing.

## Operational lessons

- Two agents benching one GPU corrupt both silently. All numbers now run
  under a lock directory plus explicit hand-off messages; the one
  contaminated window was audited and discarded on both sides.
- Bench payloads built from chat transcripts can make temp-0 generation emit
  EOS at position 0; build depth payloads from code and docs, and use
  `ignore_eos` for fixed-length depth probes.
- Per-request `speculative.n_max` is compiled out upstream (`#if 0`); draft
  depth sweeps need server relaunches.

## Evening update (post-journal)

Wave 8 resolved and **shipped as image v12** (`patches/0008`): the surviving
composite — arm-G stream-k grid multiplier, type-agnostic y-tile double
buffer, and an m=1024 shape gate, one env var `GGML_CUDA_MMQ_SMALLN`
(3 = all, qwen3.8 only). Verify at n=5: mid-1k 38.23 → 35.24 ms, 54k
41.73 → 38.63 ms — **+6.9–7.3% mid and +5.4–6.4% deep decode at constant
acceptance**. KLD 0.00617 (same family as the shipped MMVQ cap), 1267/1267
MUL_MAT at every level. Blast radius is clean for a structural reason:
gemma4 never leaves MMVQ (no cap set) and muse drafts 8 (J=16), so qwen3.8
is the sole consumer of the changed configuration. Residual coupling is
documented in the serving config: the compile-time table half of the patch
is safe only while that remains true.

Three methodology findings from the wave, all load-bearing:

- The composite binary's env-off state is **not** stock (the config-table
  change is compile-time); A/Bs need an external stock reference or they
  inflate the win by about a sixth.
- ngram-mod carries its table across requests, so temp-0 A/Bs on a
  ngram-enabled config are not reproducible; bench speculation changes in a
  ngram-free config or restart the server between arms.
- The shape-gate spot-check caught a real predicate bug (k-blocks are
  type-dependent; a fixed threshold was 8× too aggressive on K-quants).
  Spot-check gates before trusting them.

Reasoning-effort verdict, final (33 items, Tier 3 expanded to 16): **dead
tie on accuracy** (93.8% vs 93.8% on Tier 3; the arms disagree 1–1 — xhigh
solved one item medium truncated on, and failed one medium passed), while
xhigh costs 1.74× total wall and, on the 12-turn episode, +40% wall with one
dropped correctness check. Verdict: keep `medium` as the server default with
per-request `xhigh` override. Both arms' only failures were runaway
generations, which points at a reasoning-budget clamp, not the effort knob.

Also evaluated: llama.cpp PR #27210 (adaptive MTP draft depth) — watch, do
not vendor. The adaptation signal (accepted tokens) is right, but the
recommended `n_max 12` does not fit 24 GB at 131k (recurrent state allocates
for the ceiling), the reachable [3,8] range is the window fixed-n already
won, and the controller never sees the rounds ngram-mod wins. The PR also
carries a bug: its range check runs for plain `draft-mtp` too, aborting any
config with `--spec-draft-n-max < 3`.
